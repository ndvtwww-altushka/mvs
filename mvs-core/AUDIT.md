# MVS Core — audit summary

Пакет: `core-audit` → локально улучшенная поставка. Проверка выполнена локально в Java toolchain; это не Android APK и не runtime-тест Telegram-клиента.

## Что усилено

### Сетевой планировщик
- Проверка аргументов и снимок настроек запроса до постановки в очередь.
- Отмена queued-запроса освобождает место, а отмена in-flight запроса доходит до нативного handle.
- Гонка таймаута/отмены с созданием native handle закрыта: поздно созданный handle отменяется один раз.
- Отказ `ScheduledExecutorService` больше не оставляет Future и счётчики в подвешенном состоянии.
- Итеративный dispatch trampoline защищает от переполнения стека при синхронных callback.
- Shutdown завершает ожидающие и активные запросы.

### Повторы и circuit breaker
- Только явно временные ошибки допускаются к retry.
- FLOOD_WAIT не укорачивается до искусственного лимита: если ожидание выше политики, исходная ошибка возвращается вызывающему коду.
- Для всей цепочки сохраняется единый дедлайн, который не перезапускается при retry.
- Таймер retry, отмена и отказ таймерного executor завершаются предсказуемо.
- Half-open допускает одну пробу; просроченная проба переоткрывает breaker; отменённая проба освобождается без ложного учёта как сетевой ошибки.
- DC failover не заявляется как реализованный, если `nativeDcRouting` выключен.
- Значение DC по умолчанию — `AUTO_DC`, сохраняющее default route `ConnectionsManager` и не закрепляющее все запросы за DC 1.

### Формат кадров
- Проверки аргументов, длины, CRC и накопления буфера.
- Жёсткий лимит входного буфера декодера и сброс состояния при нарушении протокола.
- Исправлена структура фрагментного заголовка: зарезервированные 2 байта теперь явно записываются и проверяются, чтобы не попадать в восстановленное сообщение как пользовательские данные.
- Дубликаты, конфликтующие по содержимому, удаляют повреждённую сборку; reassembly имеет ограничения памяти и TTL.

### Журнал и криптография
- Проверка типов/длины записей при восстановлении журнала.
- Ограничение размера записи и batch до выделения крупных буферов.
- Безопасная процедура compact с временным и резервным файлами в той же директории.
- Чтение, flush, compact и close сериализуются одним writer; close останавливает приём новых операций и ждёт barrier перед закрытием файла.
- Последний write по ключу побеждает, но Future предыдущей записи также получает конечный результат.
- AES-GCM с 96-битным случайным nonce и проверкой аутентичности.

## Проверки

Команда: `sh run-tests.sh`

Результат текущей поставки:

- `RegressionTest`: **24 PASS / 0 FAIL**.
- Java API компиляции: `javac --release 17 -Xlint:all`.
- Android adapter contract: компиляция адаптера и host против `adapter-stubs/` проходит.

Тесты покрывают AES-GCM, split/coalesced frame decode, границы буфера, фрагментацию, конфликтующие дубликаты, TTL, breaker и отмену half-open пробы, синхронные callback, отмену/таймаут/гашение очереди, ретраи и единый дедлайн, устойчивость хранения/compact/close, CRC и shutdown ядра.

## Что НЕ подтверждено

- Сборка `./gradlew :TMessagesProj:compileDebugJavaWithJavac` с реальными Android-классами.
- Работа на физическом устройстве, нагрузка, battery/network transitions и многопоточность на реальных callback очередях Telegram.
- Фактическое подключение трафика приложения к `MvsNetCore`.
- Реальная per-DC маршрутизация/failover: `ConnectionsManager` остаётся владельцем физического соединения.
- Совместимость MVSP с сервером/другой стороной — в репозитории это внутренний формат, не часть MTProto.

**Статус:** улучшенный автономный JVM-компонент с зелёными локальными тестами. Не называть интегрированным или гарантированно работающим внутри APK до Android-сборки и проверки на устройстве.
